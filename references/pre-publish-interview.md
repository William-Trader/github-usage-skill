# 发布前询问清单

发布是不可逆的公开动作。**在创建仓库或推送之前，先问清楚**，不要替用户默认公开。

## 1. 必问三项（一次问完）

按顺序问，每项给推荐值；用户不回答就停在原地，不要猜。

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| 1 | 仓库可见性与授权 | 公开 + MIT / 公开 + Apache-2.0 / 公开 + PolyForm 非商业 / 私有 | 公开 + MIT（工具类）；含商业价值选 PolyForm 非商业 |
| 2 | 脱敏范围 | 全仓扫描并清理 / 只扫工作区不扫历史 / 不脱敏 | 全仓扫描（含历史提交与 README） |
| 3 | 发布内容 | 只发源码 / 源码 + release 产物 / 源码 + 示例数据 | 只发源码；产物走 release，不塞进 git |

## 2. 许可证怎么选

| 许可证 | 别人能做什么 | 适用 |
|---|---|---|
| MIT | 随便用、改、商用，保留版权声明 | 工具、示例、教程（最省事） |
| Apache-2.0 | 同 MIT，额外含专利授权与变更说明 | 企业友好、含专利风险的项目 |
| GPL-3.0 | 可商用，但衍生作品必须同样开源 | 希望强制回馈社区 |
| PolyForm Noncommercial | 仅非商业使用，商用需单独授权 | 想公开但保留商业变现 |
| 无 LICENSE | 默认保留所有权利，别人不能合法使用 | 仅私有仓库 |

补充问题（按需）：

- 是否允许商业使用？
- 是否要求保留署名/版权声明？
- 是否接受外部 PR 与 fork？
- 是否需要 CLA（贡献者许可协议）？

## 3. 脱敏清单（逐项确认）

| 类别 | 要清掉的内容 |
|---|---|
| 凭据 | API key、token、私钥、`.env`、证书、数据库密码 |
| 网络 | 公网 IP、内网域名、端口、SSH 别名、VPN 地址 |
| 路径 | `/Users/<名字>/`、`C:\Users\<名字>\`、服务器绝对路径 |
| 身份 | 真实姓名、手机号、邮箱、客户名、工单号 |
| 业务 | 未公开的财务数据、合同、内部文档、真实数据库导出 |
| 元数据 | git 历史里的旧密钥、README 里的内网链接、release 正文 |

执行顺序：

```bash
bash scripts/preflight-scan.sh .
```

扫描结果逐条给用户看，确认后再继续。**历史提交里的密钥必须轮换，清理不能替代轮换。**

## 4. 发布前确认单

- [ ] 可见性已确认（public / private）
- [ ] LICENSE 已选定并写入 `LICENSE`
- [ ] 脱敏扫描通过，命中项已处理
- [ ] 作者身份是本人 noreply 邮箱
- [ ] 仓库名、描述、topics 已确认
- [ ] 版本号与 CHANGELOG 已准备
- [ ] 用户明确说「可以发布」

## 5. 用户说「你看着办」时

用最保守组合，并明确告知：

- 私有仓库 + 无 LICENSE + 全量脱敏
- 等用户确认后再转公开

不要用「公开 + 无许可证 + 不脱敏」这种不可逆组合替用户做决定。
